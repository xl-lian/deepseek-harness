# @deepseek-ai/dsh-experimental-science-agent-bundle

Profile layer that turns dsh into a science-agent research app: auditable research campaigns (predictive modeling, scored artifact search, equation discovery) run by the external `sagent` toolkit, with role subagents, saved workflows, guard hooks, and a live loop view.

## Use this package

The layer makes the `science` Agent preset the profile default and the only selectable preset, and mounts:

- the `science-agent` and `science-agent-kaggle` skills plus eight user-invocable `/sa-*` command skills (`/sa-campaign`, `/sa-round`, `/sa-kaggle`, `/sa-status`, `/sa-verify`, `/sa-report`, `/sa-submit`, `/sa-doctor`);
- six role tools (`sa_scout`, `sa_hypothesis`, `sa_engineer`, `sa_verifier`, `sa_statistician`, `sa_reporter`), each spawning its own Agent preset from `presets/roles.patch.yml`; only `sa-engineer` can write or edit files;
- the saved workflows `science-campaign`, `science-round`, and `kaggle-round` (launched by name through `tool-workflow` `workflowDirs`); the campaign records `round_delta` and `candidates` metrics and each round report as a run artifact;
- `dsh-hooks-claude-code` with a guard that blocks direct edits to `.sa/` state and `kaggle submit`, and a trigger that turns an experiment request into a campaign;
- a stdio MCP client for the `sagent mcp serve` server (`mcp__science-agent__sa_*`);
- the [loop view and Kaggle Arena skin](../client-ui-science-loop/README.md).

### Install

The layer needs the `sagent` CLI on `PATH` (or in `~/.local/bin`) and `python3` for the hooks. Install the toolkit from a science-agent checkout:

```sh
uv tool install "science-agent-toolkit[ml,mcp] @ file:///path/to/science-agent"
```

Create a `science` profile from the Web profile (this replaces an existing `science` profile), then add this package and launch from the research workspace:

```sh
pnpm dsh --profile science --from-default-profile web --dump-config >/dev/null
pnpm dsh plugin --profile science add "$PWD/packages/experimental/science-agent-bundle"
cd /path/to/workspace && pnpm --dir /path/to/deepseek-harness dsh --profile science
```

The profile links this package; its dependency closure supplies the loop view and the hooks bridge. The MCP server and hooks use the launch directory as the default workspace.

## Content layout

| Path | Owner |
|---|---|
| `cordis.patch.yml`, `presets/roles.patch.yml`, `hooks/hooks.json`, `skills/sa-*` | this package |
| `templates/` | dsh-only text the sync inserts into science-agent sources |
| `synced/` | generated by `scripts/sync.ts` from a science-agent checkout; never edit by hand |
| `tests/fixtures/science-agent/` | generated test fixture from the same checkout |

Refresh or verify the synced content after a science-agent change:

```sh
pnpm run sync-science-agent-bundle -- --source /path/to/science-agent
pnpm run sync-science-agent-bundle -- --source /path/to/science-agent --check
```

The sync adapts the role prompts (`plugin/agents/sa-*.md`), both skills, the guard and round-trigger hooks, the MCP launcher, and the round and campaign workflows. Each step anchors on exact source text and fails with the file and anchor when science-agent changed it. `synced/MANIFEST.json` records the science-agent version and the sha256 of every source read and file written; the package tests check the committed files against it.

## Model Experience

The `science` preset carries a fixed persona, the dsh runtime note in every role persona, and the tool catalog listed above; the two science skills load on demand, and the round trigger adds one sentence to a turn whose prompt asks to run or continue experiments in a workspace with `.sa/`. Each role persona is also embedded once in each saved workflow script, which never enters the orchestrator's context. The preset text is stable across turns, so it stays in the KV-cache prefix.

## Known Limitations and Deferred Work

- The profile must link this package: the patch resolves its own root through `createRequire(baseUrl)` from the profile directory, and `pnpm dsh` installations do not list it.
- `sagent`, `python3`, and the domain pack live outside dsh; the CI tests run the synced workflows against a stub and the hooks only when `python3` exists.
- CI cannot reach science-agent, so `--check` runs only locally; a science-agent edit that moves an anchor surfaces at the next sync.
- The content synced from science-agent is Apache-2.0 upstream; licensing, locale metadata, icon and DETAIL page, and the README translation pair are not yet in place.
